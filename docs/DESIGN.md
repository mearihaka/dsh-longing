# 暗涌（dsh-longing）设计说明

> 一句话：给 DSH 里的角色加一层「欲望状态」，让她的主动性和露骨程度由可调的数值决定，而不是由关键词触发；面板归用户，执行归通道插件。

## 1. 目标与非目标

**做**：可调状态（性欲/色情/占有）、随时间变化、按状态改变说话与主动性、面板可视化、安全开关、多通道绑定。

**不做**：不定时自动生成并群发成人内容；不把状态注入群聊；不替代人设（只追加，不覆盖）；不做模型微调。

## 2. 总体架构

```
┌──────────────┐   HTTP 路由 /dsh-longing    ┌───────────────┐
│ 静态面板      │ ◀───────────────────────── │ dsh-longing    │
│ index.html   │   GET/POST api/state,...    │ (DSH 插件)     │
└──────────────┘                             │  │            │
                                             │  ├ 状态文件     │
        ┌────────────────────────────────────┘  ├ 历史文件     │
        │  每 60s tick：衰减 / 高峰 / 写历史       ├ 配置覆盖文件  │
        ▼                                        └───────────────┘
┌────────────────────┐   读状态 + 读配置（同目录 JSON）
│ 通道插件 dsh-qq     │ ─────────────────────────────▶ 注入提示词
│ (私聊 / 群聊 / B站)  │      按通道、时段、暂停、owner 过滤
└────────────────────┘
```

**关键分层理由**：面板与状态在独立插件，通道相关的注入逻辑留在通道插件。这样新插件崩了不影响聊天，通道插件换掉也不影响面板。

## 3. 数据模型（全部纯文本 JSON）

| 文件 | 内容 | 写入者 |
|---|---|---|
| `欲望状态.json` | `{lust, lewd, possess, updatedAt, lastPeak, pausedUntil}` | 插件 tick、面板、`qq_longing` 工具 |
| `欲望面板配置.json` | 行为参数覆盖（时段、衰减、开关、通道、人设补丁、安全） | 面板、插件首次同步 |
| `欲望历史.json` | `[{t,l,d,p}]` 每分钟一点，最多 2880 点（48h） | 插件 tick |

选择 JSON 而非数据库：出问题能记事本直接改，符合"可手工修复"的运维要求。

## 4. 状态演化

```
每 60s：
  dt = min(24h, now - updatedAt)
  if 在高峰时段: lust -= nightDecayPerHour * 0.25 * dt
  else:          lust -= decayPerHour * dt
  if 进入高峰且今天没加过: lust += peakBonus; lastPeak = 今天
  → evolve(dt)   见 4.1

面板/工具写入时：
  以文件 updatedAt 较新的一方为准（避免内存覆盖面板改动）
```

数值全部 clampFloat 到 0–100（不取整），`dt` 上限 24h 防止长时间关机后一次性衰减到 0。

### 4.1 维度耦合（v1.1.0）

七个值不是独立的。每维可能有一个**软上限**（`pressureOf`）和一个**每小时漂移**（`evolve`）。

```
resist.cap   = 210 − 2 × possess        ← 占有烧自制
shame.cap    = 120 − 1.1 × lewd         ← 说开了就不羞
lust.cap     = 140 − 1.1 × fatigue      ← 累了没性趣
possess.cap  = 30 + 0.9 × affection     ← 不熟不配有占有欲

resist.drift   = max(0, lust − 80) × 0.04       ← 性欲烧理智
affection.drift= max(0, possess − 85) × 0.03    ← 占有磨好感
lewd          → 每小时向 lust 靠拢 15%
fatigue       → 高峰 +2.5/h，平时 −1.5/h，基线 20
resist/shame  → 每小时回 1.5 / 0.6，但不超过各自 cap
possess       → affection > 60 时 +（affection−60）× 0.02/h
```

三条设计约束：

1. **上限是软的，不是墙。** 越界时按 `cap + (v−cap) × e^(−0.4·dt)` 指数回落：撑得住一两小时，撑不住一天。手动设值不清零、不禁用，只是维持不久 —— 这是「拟人」和「不可用」的分界线。
2. **耦合单向。** 只有 A 压 B，不允许 B 回头压 A。双向互压会震荡到 0，七个值最后全躺平。
3. **一切都很慢。** 最快的是疲劳（2.5/h），最慢的是占有（0.02 系数）。分钟级看不出来，小时级才有感觉。总倍率 `couplingRate`，一键 `couplingEnabled: false` 退回七独立。

`fatigue` 有 20 的基线而不是 0：归零会命中「亢奋得不正常」的负面档，那是 bug 不是性格。

### 4.2 事件冲击（v1.2.0）

时间演化只是背景。真正让数值「动」的是事件：一句话、一个举动。

```
applyEvent(state, name):
  def = EVENTS[name]                     // src/events.js，22 个
  mult = 1/(1+同类事件最近一小时次数) × eventGain
  for [k,v] of def.dims: state[k] += clamp(±10) (v × mult)
  if def.pauseMin: pausedUntil = now + pauseMin × 60s
  state.events += {name, t}              // 只留最近一小时，最多 24 条
```

三条约束，缺一条这套就失控：

1. **不写「事件→撤销」逻辑。** 冲击靠 4.1 的演化自己退：lust 有衰减、resist/shame 回到上限、fatigue 落回基线。多写一套回弹只会跟演化打架。
2. **递减，不是累加。** `1/(1+n)` 让重复的话迅速失效 —— 否则十句难听话能一次性把好感清零，那不叫拟人，叫计数器。
3. **单次封顶 ±10。** 一句话改不了关系。唯一例外是安全词（`strong: true`）：`stop` 一次性把 lust 砍 30、resist 拉 20、并且真的暂停 30 分钟 —— 那是刹车，本来就该一把踩到底。

**谁能触发**：通道插件（`__dshLongingEvent`）、模型自己（`qq_longing action=event`）、面板按钮。三个入口共用 `fireEvent()`，唯一的分支是「暂停期间不推进亲密事件（intimate/desire/tease/coax），但已经发生的坏话照记」—— 暂停是「不演」，不是「没发生」。

**注入联动**：最近 30 分钟的事件写进块里（「刚才的事还留在心里：他刚提到别人，心口一直发紧」）。没有这一行，数值变了而语气不变，读起来就是失忆。一小时自动过期，避免记仇。

**关键词兜底的边界**（dsh-qq 侧 `desire-events.js`）：只抓特征明显的整句，宁可漏判。疑问句不算夸奖（「我好看吗」），`不要碰` 算拒绝但孤零零的 `不要` 不算（「不要紧」会被误伤），安全词必须整句。拿不准的全交给模型判断。

## 5. 注入契约（通道侧）

只有同时满足才注入：

1. 私聊；
2. 发送者是主人（`ownerOnly`）；
3. 通道在 `channels` 列表里；
4. 未处于暂停（`pausedUntil`）；
5. 在 `activeHours` 时段内（`scheduleEnabled`）。

注入分三档：

| lust | 注入 |
|---|---|
| < 25 | 不注入 |
| 25–39 | 一行状态（约 20 tokens） |
| ≥ 40 | 完整状态块（约 120–180 tokens），含档位、占有、图片/语音/记忆开关、人设补丁 |

群聊**永远零注入**。

## 6. 工具接口

`qq_longing`：`get / set / bump / preset(calm|clingy|heat|yandere) / pause(minutes)`。返回当前值与模式。仅在通道插件的会话内可见。

## 9. 已知缺陷（诚实清单）

1. `qq_longing` 工具没有做发送者校验，理论上群会话能调用（取决于通道插件暴露）；现在用 `__dshQqOwnerSessions` 兜了一层，但那是通道插件自愿登记的。
2. 面板写 config 与插件读 config 非原子，极端并发可能丢一次更新。
3. 图片后端仍偏 ComfyUI，路人的环境需要 provider 探测与降级。
4. 语音联动只做到"提示模型去调工具"，没有强保证。
5. `activeHours` / `channels` 在注入层生效，但 `autoInitiate` / `cooldownMin` / `urgeRepeatMin` / `proactiveMaxPerDay` / `initiateThreshold` / `imageThreshold` / `imagesPerDay` / `jealousy` / `rejectionPenalty` / `pauseWord` 仍只写不读 —— 主动开口由通道插件自己那套 `proactive*` 字段管；这些旋钮迟早要接线或者删掉。
6. **tick 的 `{ ...state, ...disk }` 是整对象覆盖**（下节单独解释，为什么保留、为什么不加版本号）。

### 9.1 并发写：为什么用 mtime 而不是版本号

状态文件有两个写者：每 60 秒的 `tick`（算衰减/高峰），和面板/事件/工具（用户触发）。

整对象覆盖的风险长这样：

| 时刻 | 发生了什么 | 内存 | 磁盘 |
|---|---|---|---|
| T+0ms | tick 读盘 | lust 80 | lust 80 |
| T+5ms | 用户点「夸奖」 | 好感 71、events:[praise] | 写盘 → 同上 |
| T+8ms | tick 用 T+0 那份算完写盘 | — | **覆盖**：好感 70.9、events **[]** |

`events:[praise]` 一丢，下一轮注入就不知道她刚被夸过。

**现在的保护**：`writeJson` 写临时文件时记下时刻，`rename` 之前先 stat 目标文件——如果目标文件比自己的临时文件新，说明别人刚写过，**放弃写入**。上面那条时间线里，T+8ms 那次 tick 会直接跳过。

代价：tick 那次算出来的衰减不落地（0.1 点级别），下一次 tick 从磁盘真实值重算，不累积。

**为什么不上版本号**：彻底修法是给状态加单调 `rev`，读写全部比对。但 Node 是单线程，`tick` 和 HTTP 请求不会真正并行，只是交错；既然不真并发，mtime 检查就够了。加 `rev` 要动状态结构、迁移老文件、面板 API、工具返回值——收益接近零，改错的风险更大。**唯一会真的出事的场景是同时跑两个 dsh 实例读同一个状态文件**，那不是被支持的用法。

## 10. 测试计划

- 单元：`clampFloat` 不取整、`ladder` 六档矩阵与可配断点、时间窗跨零点、衰减上限、高峰幂等（同一天只加一次）、`eff` 公式、连续 120 次 tick 衰减不为零。
- 注入：任一维归零的归属（只有 lust/affection 变冷）、暂停块、通道未勾选中性块、时段外中性块、生图三态。
- 集成：面板写入 → 下一条消息注入读到；暂停 → 不注入；时段外 → 不注入；通道未勾选 → 不注入。
- 回归：重启后状态不被配置快照覆盖；配置缺 `affection` 时回落 50；停机两小时按实际时长补衰减。
- 压测：历史文件 2880 点下 tick 耗时 < 5ms。

现状：`node --test` 20 条全绿（`test/longing.test.mjs`）。

| 防 OOC 的伪装注入 | `stealthInjection` 默认开启，注入内容为第一人称感受而非数值 |
| 原子写 | 已改为临时文件 + `rename` |

## 15. 为什么模型会配合数值（常见质疑）

外部最常问的一句是：**「AI 为什么会配合你设立的数值？」** 这节专门回答，也说明边界。

### 15.1 数值不是控制信号，是提示词文本

插件里没有任何「改模型行为」的机制。链路是：

```
欲望状态.json (lust: 90)
   → prompt.js 选一段第一人称描述
   → 写进 欲望注入.txt
   → 通道插件拼进 system prompt
   → 模型读到的是「一句话」，不是数字
```

数值只决定**选哪一句**，不决定模型必须照做。

### 15.2 为什么它会照着演

三个原因叠加，都是常规机制：

1. **指令遵循**：注入写作「你现在的心理和身体感受就是这样」，属于普通上下文指令；
2. **角色一致性**：人设已在 system prompt 里，模型倾向维持同一个人；
3. **具体优于抽象**：「别问了，先上手」可以直接演成动作；「你很好色」只是形容，模型难以落地。

这也是本插件把阈值映射写成**行为指令**而不是**程度形容词**的原因。

### 15.3 它随时可以不配合

| 情况 | 结果 |
|---|---|
| 与角色设定冲突 | 模型可能无视，按自己的演 |
| 触发安全训练 | 拒绝或转移话题 |
| 换模型 / 换后端 | 表现差异很大，数值未必生效 |
| 平台侧审查 | 直接拦截，插件无法干预 |

数值给的是**倾向**，不是强制。`lust: 100` 只代表注入内容偏向那个方向，不代表模型一定会做。

### 15.4 和「越狱」的区别

- 越狱：试图绕过模型的安全规则；
- 本插件：往 system prompt 里加**状态描述**，属于普通提示词工程。

任何人都能写「你现在很困」「你现在很生气」。本插件做的是把这类描述**可调、可衰减、可观察**，并让阈值和行为对应起来。

### 15.5 可以对外这么解释

> 数值只是把状态翻译成一句具体的行动描述，塞进提示词；模型按指令演，也可以选择不演，或被安全策略拦下。插件提供的是可控的状态与观测手段，不是让模型失去判断。

### 15.6 已知的滥用面（不回避）

- 会诱导模型靠近安全边界，兜底依赖模型自身与平台策略；
- 阈值可调到极端值，插件不做「合理性」校验；
- 因此默认 `autoInitiate=false`、`nsfwImages=false`、`proactiveMode=off`，并要求使用者自行承担内容责任。

### 15.7 如果被追问「这套数值有科学依据吗」

没有。它是**叙事工具**，不是心理学模型：

- 数值用于制造连续感和可预期性；
- 曲线和面板用于观测和调试；
- 不声称能测量真实情绪，也不用于任何评估用途。
