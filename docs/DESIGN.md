# 暗涌（dsh-longing）设计说明

> 一句话：给 DSH 里的角色加一层「欲望状态」，让她的主动性和露骨程度由可调的数值决定，而不是由关键词触发；面板归用户，执行归通道插件。

## 1. 目标与非目标

**做**：可调状态（性欲/色情/占有）、随时间变化、按状态改变说话与主动性、面板可视化、安全开关、多通道绑定。

**不做**：不定时自动生成并群发成人内容；不把状态注入群聊；不替代人设（只追加，不覆盖）；不做模型微调。

## 2. 总体架构

```
┌──────────────┐   HTTP 路由 /dsh-longing    ┌───────────────┐
│ 静态面板      │ ◀───────────────────────── │ dsh-longing    │
│ index.html   │   GET/POST api/state,...    │ (DSH 插件)     │
└──────────────┘                             │  │            │
                                             │  ├ 状态文件     │
        ┌────────────────────────────────────┘  ├ 历史文件     │
        │  每 60s tick：衰减 / 高峰 / 写历史       ├ 配置覆盖文件  │
        ▼                                        └───────────────┘
┌────────────────────┐   读状态 + 读配置（同目录 JSON）
│ 通道插件 dsh-qq     │ ─────────────────────────────▶ 注入提示词
│ (私聊 / 群聊 / B站)  │      按通道、时段、暂停、owner 过滤
└────────────────────┘
```

**关键分层理由**：面板与状态在独立插件，通道相关的注入逻辑留在通道插件。这样新插件崩了不影响聊天，通道插件换掉也不影响面板。

## 3. 数据模型（全部纯文本 JSON）

| 文件 | 内容 | 写入者 |
|---|---|---|
| `欲望状态.json` | `{lust, lewd, possess, updatedAt, lastPeak, pausedUntil}` | 插件 tick、面板、`qq_longing` 工具 |
| `欲望面板配置.json` | 行为参数覆盖（时段、衰减、开关、通道、人设补丁、安全） | 面板、插件首次同步 |
| `欲望历史.json` | `[{t,l,d,p}]` 每分钟一点，最多 2880 点（48h） | 插件 tick |

选择 JSON 而非数据库：出问题能记事本直接改，符合"可手工修复"的运维要求。

## 4. 状态演化

```
每 60s：
  dt = min(24h, now - updatedAt)
  if 在高峰时段: lust -= nightDecayPerHour * 0.25 * dt
  else:          lust -= decayPerHour * dt
  if 进入高峰且今天没加过: lust += peakBonus; lastPeak = 今天

面板/工具写入时：
  以文件 updatedAt 较新的一方为准（避免内存覆盖面板改动）
```

数值全部 clamp 到 0–100，`dt` 上限 24h 防止长时间关机后一次性衰减到 0。

## 5. 注入契约（通道侧）

只有同时满足才注入：

1. 私聊；
2. 发送者是主人（`ownerOnly`）；
3. 通道在 `channels` 列表里；
4. 未处于暂停（`pausedUntil`）；
5. 在 `activeHours` 时段内（`scheduleEnabled`）。

注入分三档：

| lust | 注入 |
|---|---|
| < 25 | 不注入 |
| 25–39 | 一行状态（约 20 tokens） |
| ≥ 40 | 完整状态块（约 120–180 tokens），含档位、占有、图片/语音/记忆开关、人设补丁 |

群聊**永远零注入**。

## 6. 工具接口

`qq_longing`：`get / set / bump / preset(calm|clingy|heat|yandere) / pause(minutes)`。返回当前值与模式。仅在通道插件的会话内可见。

## 7. 面板 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/dsh-longing` | 静态面板（含壁纸） |
| GET/POST | `/dsh-longing/api/state` | 读写三值 |
| GET/POST | `/dsh-longing/api/config` | 读写行为参数 |
| GET | `/dsh-longing/api/history` | 曲线数据 |
| POST | `/dsh-longing/api/preset` | 套预设 |

## 8. 安全设计（威胁模型）

| # | 威胁 | 现状 | 建议 |
|---|---|---|---|
| T1 | 本机任意程序改面板 | **无鉴权**，仅绑定回环地址 | 加本地 token（启动时生成，写进状态目录，面板首屏输入一次） |
| T2 | 浏览器跨站请求伪造 | 无 CSRF 保护，但同源 + 回环降低风险 | 加 `Origin` 校验 + 自定义 header |
| T3 | 状态文件泄露亲密信息 | 明文 JSON | README 明确警告；`.gitignore` 排除；可选 AES 加密（不做默认） |
| T4 | 群友/他人诱导角色越权 | 注入只在主人私聊；群聊零注入 | 保持；`qq_longing` 工具仍需 owner 校验 |
| T5 | 提示词注入（图片文字、引用内容） | 状态块来自本地文件，不来自消息 | 不把外部文本拼进状态块 |
| T6 | 成人图生成合规 | 默认 `nsfwImages=false`，需显式开启 | 保持默认关；云端生图要考虑服务商条款 |
| T7 | 日志泄露 | 已加脱敏：身份证/卡号/手机/token/密码/邮箱在写日志前替换为 *** | 保留期仍待做 |
| T8 | 依赖供应链 | 仅依赖宿主提供的 schemastery | 锁定版本，不引入运行时第三方 |
| T9 | DoS / 磁盘增长 | 历史有上限 2880 点 | 已有上限；再加文件大小告警 |
| T10 | 多用户/多实例 | 单 profile 假设 | 状态路径可配置，天然支持多实例隔离 |

## 9. 已知缺陷（诚实清单）

1. 面板无鉴权（T1），目前靠"只绑定 127.0.0.1"。
2. `qq_longing` 工具没有做发送者校验，理论上群会话能调用（取决于通道插件暴露）。
3. 面板写 config 与插件读 config 非原子，极端并发可能丢一次更新。
4. 插件重启会把面板改过的三值同步为配置默认值（当前行为，需在产品上说明）。
5. 图片后端仍偏 ComfyUI，路人的环境需要 provider 探测与降级。
6. 语音联动只做到"提示模型去调工具"，没有强保证。

## 10. 测试计划

- 单元：clamp、时间窗跨零点、衰减上限、高峰幂等（同一天只加一次）。
- 集成：面板写入 → 下一条消息注入读到；暂停 → 不注入；时段外 → 不注入；通道未勾选 → 不注入。
- 回归：群聊零注入；owner 以外零注入。
- 压测：历史文件 2880 点下 tick 耗时 < 5ms。

## 15. 为什么模型会配合数值（常见质疑）

外部最常问的一句是：**「AI 为什么会配合你设立的数值？」** 这节专门回答，也说明边界。

### 15.1 数值不是控制信号，是提示词文本

插件里没有任何「改模型行为」的机制。链路是：

```
欲望状态.json (lust: 90)
   → prompt.js 选一段第一人称描述
   → 写进 欲望注入.txt
   → 通道插件拼进 system prompt
   → 模型读到的是「一句话」，不是数字
```

数值只决定**选哪一句**，不决定模型必须照做。

### 15.2 为什么它会照着演

三个原因叠加，都是常规机制：

1. **指令遵循**：注入写作「你现在的心理和身体感受就是这样」，属于普通上下文指令；
2. **角色一致性**：人设已在 system prompt 里，模型倾向维持同一个人；
3. **具体优于抽象**：「别问了，先上手」可以直接演成动作；「你很好色」只是形容，模型难以落地。

这也是本插件把阈值映射写成**行为指令**而不是**程度形容词**的原因。

### 15.3 它随时可以不配合

| 情况 | 结果 |
|---|---|
| 与角色设定冲突 | 模型可能无视，按自己的演 |
| 触发安全训练 | 拒绝或转移话题 |
| 换模型 / 换后端 | 表现差异很大，数值未必生效 |
| 平台侧审查 | 直接拦截，插件无法干预 |

数值给的是**倾向**，不是强制。`lust: 100` 只代表注入内容偏向那个方向，不代表模型一定会做。

### 15.4 和「越狱」的区别

- 越狱：试图绕过模型的安全规则；
- 本插件：往 system prompt 里加**状态描述**，属于普通提示词工程。

任何人都能写「你现在很困」「你现在很生气」。本插件做的是把这类描述**可调、可衰减、可观察**，并让阈值和行为对应起来。

### 15.5 可以对外这么解释

> 数值只是把状态翻译成一句具体的行动描述，塞进提示词；模型按指令演，也可以选择不演，或被安全策略拦下。插件提供的是可控的状态与观测手段，不是让模型失去判断。

### 15.6 已知的滥用面（不回避）

- 会诱导模型靠近安全边界，兜底依赖模型自身与平台策略；
- 阈值可调到极端值，插件不做「合理性」校验；
- 因此默认 `autoInitiate=false`、`nsfwImages=false`、`proactiveMode=off`，并要求使用者自行承担内容责任。

### 15.7 如果被追问「这套数值有科学依据吗」

没有。它是**叙事工具**，不是心理学模型：

- 数值用于制造连续感和可预期性；
- 曲线和面板用于观测和调试；
- 不声称能测量真实情绪，也不用于任何评估用途。
